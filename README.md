# TTG Ops

Private clinical oversight front-end for Together They Grow. Phone-first, six portals from a clean Home:
Students & Cases · Clinical Notes · Providers & Schedules · Billing Review · Reports & Updates · Email & Open Items.

Front-end only in this public repo. Live case data comes from a private, key-protected Apps Script API and is kept in
memory only (never in localStorage, links, or the service-worker cache). No admin keys, clinical exports, Ensora files or
real records belong here.

- **Live:** open with your personal admin link (stores the key on this device and strips it from the address bar).
- **Fictional preview:** add `?fixtures=1`. Uses generated fictional data through an in-memory stand-in; makes no network
  requests even if a key is stored, and nothing is saved.

| File | Purpose |
| --- | --- |
| `app.js` | UI, routes and actions (event delegation; all text escaped) |
| `model.js` | Pure mapping of the real API responses into the portal view model, notes filters, notes-grounded report drafts, search |
| `billing-core.js` | Billing review rules shared with the API (copied there as `BillingCore.gs`) |
| `fixtures/v4-sample.js` | Fictional data generated by running the real API code against fake sheets |
| `fixtures/fake-api.js` | In-memory API stand-in for fixture mode only |
| `tests/` | `npm test` — model, billing rules, auth/route contract, XSS, privacy, no-send, service worker |

Nothing in TTG Ops sends email or texts. Approving a draft marks it for Katya to send; billing sign-off records a decision
only (no invoices or payments).

See `docs/DEPLOY_PREREQUISITES.md` before deploying.
